# Digital Twin Framework: Predictive & Interrogative Roles

This project provides an architectural overview and operational model for implementing **Predictive Digital Twins** and **Interrogative Digital Twins** within IoT and cyber-physical systems (CPS). It outlines how data querying and machine learning predictions interact across physical entities and their virtual replicas.

## Overview

Digital Twins act as dynamic, real-time virtual representations of physical assets, processes, or systems. Depending on the decision-making horizon and interaction model, a Digital Twin serves two primary roles: **Querying (Interrogative)** and **Predicting (Predictive)**.

## Core Roles & Capabilities

### 1. Interrogative Digital Twin (Query Role)

The **Interrogative Digital Twin** enables operators, automated systems, and analytical engines to query the current and historical states of the physical asset.

* **Primary Function:** State retrieval, diagnostic inspection, and audit trail analysis.
* **Core Mechanisms:**
* Time-series telemetry querying (e.g., SQL/NoSQL, GraphQL, TSDB).
* Contextual knowledge graphs linking sensors, subcomponents, and maintenance records.
* Spatial and structural state queries ("What is the current temperature across Node 4?").


* **Key Questions Answered:**
* *What is the current operational state?*
* *When did the last anomaly occur?*
* *How has parameter X correlated with output Y over the past 30 days?*


### 2. Predictive Digital Twin (Prediction Role)

The **Predictive Digital Twin** leverages machine learning, physics-based simulations, and statistical modeling to forecast future states, system degradation, and failure modes under varying conditions.

* **Primary Function:** Anticipatory analysis, anomaly forecasting, and synthetic scenario evaluation.
* **Core Mechanisms:**
* Deep Reinforcement Learning (DRL) and Time-Series Forecasting (e.g., LSTMs, Transformers).
* Reduced-Order Modeling (ROM) and finite element physical simulations.
* "What-if" scenario simulation engines.


* **Key Questions Answered:**
* *When is Component Z likely to fail given the current wear rate?*
* *How will system stability change if ambient temperature increases by $5^\circ\text{C}$?*
* *What is the optimal control policy to maximize throughput over the next 24 hours?*


## Comparative Matrix

| Feature / Dimension | Interrogative Digital Twin | Predictive Digital Twin |
| --- | --- | --- |
| **Temporal Focus** | Past and Present ($t \le t_0$) | Future ($t > t_0$) |
| **Primary Data Input** | Ingested sensor telemetry, event logs, metadata | Historical baselines, ML model weights, physics solvers |
| **Output Type** | Exact state values, filtered traces, audit logs | Probabilistic distributions, remaining useful life (RUL), control policies |
| **Core Query Mechanism** | Database index queries, API REST/gRPC lookup | Forward simulation passes, model inference calls |
| **Primary Use Cases** | Condition monitoring, root-cause diagnostics, compliance | Predictive maintenance, optimization, risk assessment |


## Technical Stack & Architecture

1. **Ingestion & Transport:** MQTT, Kafka, gRPC for edge-to-cloud telemetry sync.
2. **State Store (Interrogative):** InfluxDB / TimescaleDB for time-series data; Neo4j for structural asset mapping.
3. **Analytics & Inference (Predictive):** PyTorch / TensorFlow pipelines, ONNX runtime for low-latency edge prediction, Python/C++ simulation engines.
4. **Interface:** RESTful API and WebSockets for real-time state streaming and query execution.
