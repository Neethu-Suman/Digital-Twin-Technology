Since you are starting with **NVIDIA Omniverse** for **Industrial Digital Twins**, the single most important technology you need to learn is **Universal Scene Description (OpenUSD)**.

Omniverse is built entirely on USD. To programmatically interact with a digital twin, you must learn the USD Python API.

Here is a foundational "Hello, World" program to get you started. This script creates a new **OpenUSD scene**, adds a 3D **cube** to it (an asset twin), and **names** the asset, all within the Omniverse environment.

### "Hello World" Digital Twin Creation Script

This script is designed to be run directly inside **NVIDIA Omniverse Code** (the primary IDE for Omniverse development).

#### Instructions to Run the Script:

1. Open **Omniverse Code** from your Omniverse Launcher.
2. In the main menu, go to **Window** > **Script Editor**.
3. Copy and paste the entire script below into the **Python script panel** on the right side.
4. Click the **Run** button (the arrow icon) above the script panel.
5. Watch the **Viewport** in Omniverse Code to see your scene appear.

```python
"""
Omniverse Hello World for Digital Twins:
Programmatically create a foundational OpenUSD scene with a dynamic cube.
This is the base layer for Component & Asset Twins.
"""

import math
from pxr import Usd, UsdGeom, Gf

def create_basic_asset_twin():
    print("\n--- Starting 'Hello, World' Digital Twin Setup ---")

    # [1] AGGREGATION & OPENUSD CONVERSION: Set Up the USD Stage
    # Instead of importing, we programmatically create the foundation scene.
    stage = Usd.Stage.CreateNew("HelloWorldTwin.usd")
    
    # Define a high-fidelity visual and physics-capable root transform (Xform).
    root_prim = UsdGeom.Xform.Define(stage, "/WorldTwin")
    print(f"Created Root Primary Xform at: {root_prim.GetPath()}")
    
    # Make this the default prim so other tools reference it correctly.
    stage.SetDefaultPrim(root_prim.GetPrim())

    # [2] ASSET DEFINITION: Define the Basic Asset (Component Twin)
    # Define a mesh for the asset, in this case, a 'Box' (cube).
    print("Defining 3D Asset: DynamicCube...")
    box_path = root_prim.GetPath().AppendChild("DynamicCube")
    box_prim = UsdGeom.Cube.Define(stage, box_path)
    
    # Configure high-fidelity visual appearance (Size).
    # Since it is a 'Hello World', we keep the scaling simple (size=10).
    box_prim.CreateSizeAttr(10.0)

    # Configure high-fidelity kinematic property (Translation).
    # We apply an initial 'move' (translation) in 3D space (Gf.Vec3d).
    # This represents setting an initial state for kinematic rigging.
    init_trans = Gf.Vec3d(25, 0, 50)
    print(f"Applying Initial Kinematic Translation: {init_trans}")
    UsdGeom.XformCommonAPI(box_prim).SetTranslate(init_trans)
    
    # Save the OpenUSD scene.
    stage.GetRootLayer().Save()
    print("--- Digital Twin Foundation Scene Created Successfully! ---")
    print(f"Scene Saved to: HelloWorldTwin.usd\n")

if __name__ == "__main__":
    # Ensure this script runs within the Omniverse Python environment context.
    # Note: When running in Omniverse Script Editor, this guard is sometimes ignored.
    # It is safer to define a function and call it, which works in all contexts.
    create_basic_asset_twin()

```

### What this Script Accomplishes (Workflow References)

This script implements the foundational steps of creating a simple component/asset twin:

1. **Stage Creation (OpenUSD):** It initializes a dynamic scene where visual and physical assets will be composited. This is the **aggregation layer** for your digital twin.

2. **Primitive Definition (Component Twin):** It defines a new primitive—a **cube**—inside the scene hierarchy. This represents programmatically creating a digital reflection of a simple **component or asset**.

3. **Kinematic Transformation (Rigging Base):** It sets an initial **translation** (position) for the cube. Programmatically modifying transforms (position, rotation, scale) is how you automate the movement of robotic arms or conveyors once you connect live **IoT/telemetry feeds** in advanced stages.

4. **Save as OpenUSD:** The output is a `.usd` file, which is the native, modular data schema of Omniverse.
